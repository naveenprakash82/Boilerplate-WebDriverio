# JUnit XML converter

The JUnit XML converter reads a deliberately limited subset of local JUnit-style reports and emits the toolkit's test-run JSON records. It is not a general-purpose XML reader and has not been validated against every JUnit reporter.

## Example

```bash
npm ci
npm run junit:convert -- ci-001 examples/sample-junit-report.xml > converted.json
npm run analyze -- converted.json
```

The converter trims surrounding whitespace from the supplied run ID and assigns it to each record. A test identifier combines the suite name, testcase class name (or suite name if omitted), and testcase name. The same identifier must be unique within one report.

## Supported XML

- A single `<testsuite>` root or a `<testsuites>` root containing direct `<testsuite>` children.
- Named `<testcase>` entries, optionally with a `classname` and a nonnegative decimal `time` in seconds.
- `<failure>` or `<error>` as failed outcomes, `<skipped>` as skipped, and no marker as passed.
- Optional suite-level `<properties>`, `<system-out>`, and `<system-err>`, plus testcase-level output nodes. These are ignored.
- Declared `tests`, `failures`, `errors`, and `skipped` totals on suites and the aggregate root, when present. Totals must match parsed testcase outcomes.

## Input restrictions

The converter rejects DTD declarations, XML processing instructions, namespaces, unsupported nesting, duplicate test IDs, conflicting outcome markers, invalid times (including on skipped testcases), and inconsistent declared counts. It limits XML input to 1 MiB, 100 suites, and 5,000 testcases. It does not resolve external entities or fetch network resources.

The converter intentionally rejects unsupported XML shapes rather than guessing their meaning. In particular, nested suites, additional testcase children, and reporter-specific extensions are not accepted. XML variants generated by different tools may require separate adapters or additional compatibility tests.

A report conversion is not evidence of an independent test execution. Use distinct run IDs and retain the original source reports for reproducibility. Only share public or synthetic fixtures.
